# Каркас бота для подбора вакансий

Это открытый обезличенный каркас для **одного запуска** поиска и отбора вакансий. Сейчас он читает сохранённую страницу вакансии или страницу поиска на `remote-job.ru`, применяет правила из выбранного JSON-профиля и выводит карточки. Без `--profile-file` используется включённый в пакет вымышленный профиль. Отправка карточек в Telegram включается отдельным флагом. Непрерывный мониторинг, другие сайты, Deep Research и оценку нейросетью нужно добавлять под свои задачи. В репозитории нет профиля владельца, его аккаунтов и токенов; примеры вымышленные.

![Как профиль превращает вакансию в карточку](docs/demo-card.svg)

**Быстрый запуск** (Python 3.11 или новее):

```powershell
git clone https://github.com/PaleSyntax/remotejob-bot-framework.git
cd remotejob-bot-framework
python -m venv .venv
.venv\Scripts\python -m pip install -e .
.venv\Scripts\python -m remotejob_bot --demo --profile ai_automation
```

На macOS/Linux в двух последних строках используйте `.venv/bin/python`. Установка через `-e` ссылается на эту папку: для запуска из другого каталога оставьте клон на месте. Вымышленные HTML-страницы и профиль входят в Python-пакет; для `--demo` сеть, Telegram и токены не нужны (сеть может понадобиться `pip` при установке зависимостей).

## Что умеет этот каркас

| Режим | Что происходит |
| --- | --- |
| `--demo` | Три вымышленные HTML-страницы проходят через парсер и выбранный профиль (по умолчанию встроенный вымышленный). Сеть, Telegram и токены не нужны. Балл зависит от ключевых слов и признака удалённой работы. |
| `run-once --html` | Читает сохранённую HTML-страницу вакансии в формате `remote-job.ru` и показывает карточку после фильтров. Запросов в сеть нет. |
| `run-once --search-url` | Один раз открывает указанную HTTPS-страницу поиска на `remote-job.ru`. По умолчанию разбирает до 3 вакансий с каждой страницы и выводит не более 3 подходящих карточек. Работа с текущей структурой живого сайта не подтверждена и может потребовать обновления парсера. |
| `run-once ... --telegram` | Отправляет полученные карточки в ваш чат через Telegram Bot API. Отправка происходит только с этим флагом. |

Нижняя граница зарплаты и удалённость могут отсеять вакансию. Балл для прошедших фильтр вакансий складывается из совпадений ключевых слов и бонуса за удалённую работу. Черновики откликов не создаются, работодателям бот не пишет. Живые `remote-job.ru` и Telegram при подготовке этого каркаса не проверялись: тесты соответствующих HTTP-вызовов используют подменённые ответы.

## Источники вакансий и Deep Research

**В этом репозитории есть один источник вакансий:** `remote-job.ru`. `run-once --search-url` принимает только его HTTPS-адреса, а `enabled_sources` поддерживает только `remotejob`. Сохранённый HTML через `--html` тоже разбирается парсером вакансий `remote-job.ru`; произвольный сайт через этот флаг не подключается. Живую совместимость с сайтом при публикации каркаса не проверяли.

В закрытом исходном приложении есть код пяти площадок: `remote-job.ru`, `hh.ru`, Habr Career, `designer.ru` и `HireHi.ru`. В чистую копию перенесён только первый парсер; остальные реализации и их работа на живых сайтах здесь не проверены. Чтобы добавить свой сайт, напишите адаптер, который приводит его вакансии к общему формату `RawVacancy`. Интерфейс `VacancySource` описан в `models.py`. Зарегистрируйте источник в `search_profiles/registry.py`, подключите его в `run_once.py` и проверьте на примере страницы или ответа API.

**Deep Research в этом репозитории отсутствует.** В закрытом исходном приложении есть пять режимов запроса (`general`, `job`, `skills`, `vibe`, `vacancy`) и реализации пяти поисковых провайдеров: Exa, Tavily, Brave Search, SerpAPI и DuckDuckGo Instant Answer. Их код, команда `/research` и результаты работы не входят в чистый каркас. Для своей версии нужно отдельно добавить провайдеры, объединение результатов и нужные режимы; ключи платных API хранить в игнорируемом `.env`. Наличие кода в закрытой версии не подтверждает, что каждый провайдер сейчас отвечает на живой запрос.

LLM в этой версии **не подключён**. Место для собственной модели — `pipeline.evaluate`; парсер и отправка в Telegram вынесены отдельно.

## Подключение своей нейросети

Каркас не привязан к конкретной нейросети. Чтобы использовать свою модель, добавьте **адаптер под свои задачи и её API**: небольшой модуль, который передаёт вакансии модели и возвращает результат для оценки. Подключить его можно в `pipeline.py` / `run_once.py`. Вы сами решаете, какие данные адаптер отправляет внешнему сервису.

Ключ выбранного сервиса храните в `.env`: скопируйте `.env.example` в `.env` и заполните `AI_API_KEY`. Файл `.env` исключён из Git. Адаптер должен загрузить этот файл (например, через `python-dotenv`) и прочитать ключ из окружения. Адрес API, формат запроса и название модели настройте под выбранный сервис.

**Сейчас одного ключа недостаточно:** готового LLM-адаптера нет, `AI_API_KEY` основным кодом не читается, а `--demo` и `run-once` продолжают работать по прозрачным правилам. Не вписывайте ключ в JSON-профиль или исходный код.

## Настройте под себя

1. Скопируйте `profiles/example.json` в `profiles/local.json`. Файл `local.json` игнорируется Git.
2. Замените вымышленные `profile_text`, `heuristic_keywords` и название профиля своими. Ключ `ai_automation` можно оставить для команд ниже; если меняете его, замените и значение `--profile` в командах. В `enabled_sources` сейчас допустим только `remotejob`; другие названия заработают после добавления адаптеров и регистрации в коде.
3. Для поиска вставьте адрес страницы результатов `remote-job.ru` в `remotejob_search_urls`. Для локальной HTML-страницы этот список можно оставить пустым.

Текущий профиль выбирается `--profile`. Порог балла задаётся `--min-score`, минимальная предложенная зарплата через `--min-salary`, требование удалёнки через `--remote-only`. При заданном `--min-salary` вакансия проходит только если известная нижняя граница зарплаты не меньше порога; вакансия только с верхней границей или без зарплаты исключается. Поле `presentation_policy` позволяет записать собственные правила подачи опыта. Оно и поля `eval_context`, `pipeline_context`, `resume_context`, `digest_context` предназначены для будущего LLM-адаптера. **В этой версии они не применяются:** балл зависит от ключевых слов и удалённости, зарплата только фильтрует; черновики откликов не создаются.

```powershell
.venv\Scripts\python -m remotejob_bot run-once --html fixtures/automation.html --profile-file profiles/local.json --profile ai_automation --remote-only
```

Эта команда выполняется из корня клона. Из другой папки передайте абсолютные пути в `--html` и `--profile-file`. Если `--profile-file` не задан, используется вымышленный профиль, включённый в пакет.

Для живого поиска передайте полный HTTPS-адрес страницы результатов `remote-job.ru` через `--search-url` либо заполните `remotejob_search_urls` в профиле. Запросы выполняются только при `run-once`; демонстрация всегда офлайн. Если разметка сайта изменилась, парсер нужно адаптировать.

## Отправка в Telegram

Скопируйте `.env.example` в `.env`, впишите токен **своего** бота и ID **своего** чата. `.env` исключён из Git. Можно вместо файла задать переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

```powershell
.venv\Scripts\python -m remotejob_bot run-once --html fixtures/automation.html --profile-file profiles/local.json --profile ai_automation --telegram
```

При действительном токене, ID чата и доступном Telegram команда пытается отправить подходящие карточки по вашему `profiles/local.json`. Сначала проверьте вывод той же команды без `--telegram`. Живая отправка этого публичного каркаса не подтверждена; в тестах Telegram подменён. Бот не откликается на вакансии и не пишет работодателям.

## Проверка и развитие

```powershell
.venv\Scripts\python -m pip install -r requirements-test.txt
.venv\Scripts\python -m pytest -q
```

В тестах проверяются два разных вымышленных профиля, локальная HTML-страница, поиск с подменённым HTTP-транспортом, ограничения по зарплате и удалёнке, а также отправка через подменённый Telegram-транспорт. Для своего источника добавьте адаптер, который возвращает `RawVacancy`; правила отбора находятся в `pipeline.py`, отправка в `run_once.py`.

**English:** A configurable one-shot vacancy-bot skeleton with fictional offline examples. The bundled parser targets `remote-job.ru`; live site compatibility and Telegram delivery have not been verified. Other job sites need their own adapters. Five web-search providers implemented in the private original are not bundled here. You can add your own model adapter and keep its key in the ignored `.env` file. Continuous monitoring and LLM evaluation are not included.
